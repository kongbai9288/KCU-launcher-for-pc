## 怎么运作

按权重生成探测计划：分出无成功记录的一组，其余按权重取前 N 台（N 由设备档位给），新加服务器强制排队首且占同一份额度。N 台放进有界队列，最多 C 路同时在线；UI 先渲染上次结果，结果逐条增量写回。范围外不发请求、保留上次结果。标准 4 台 / 3 路，轻量 2 台 / 2 路，无界面 0；台数与并行数可在设置里改。停止按钮取消后不再写新结果、不再发新请求。

| 项 | 值 |
| --- | --- |
| 实现状态 | 演示层；`src/` 本轮无变化 |
| 输入 | `ui.demo / servers.probe` |
| 输出 | 增量渲染的服务器列表、预算四格与进度条、`[KCU]` 诊断行 |
| 错误路径 | 单台超时跳过、取消后 0 新请求、失败不毁整批 |
| 空值 | 没有服务器给添加入口；档位 0 给「本次不连」 |
| 超时 | 单台 deadline，慢源跳过 |
| 排除项 | 不随服务器总数线性扩连接数；不无限堆积队列 |

## 开放了什么

| 接口 | 类型 | 输入 | 输出 | 错误 |
| --- | --- | --- | --- | --- |
| `srvProbe(soft)` | 函数 | 是否增量 | 异步计划与增量渲染 | 已在跑则忽略 |
| `buildPlan()` | 函数 | 无 | probe / out / never 三组 | 档位 0 给空计划 |
| `srvCancel()` | 按钮 | 无 | 停止本次同步 | 未在跑则忽略 |
| `srvSwitchTier()` | 按钮 | 无 | 标准 / 轻量切换并重排 | 无 |
| `setBudLimit` / `setBudConc` / `setBudTier` | 设置 | 数值 | 改档位并重算计划 | 无 |
| `srvAdd()` | 按钮 | 无 | 新服强制入队 | 仍卡在 N 内 |

## 用户使用逻辑

| 入口 | 动作 | 结果 |
| --- | --- | --- |
| 服务器页 | 打开 / 点重新连接 | 后台连 N 台，界面先显示上次结果 |
| 添加服务器 | 填完地址 | 一定连一次，但不会多占额度 |
| 连接范围卡 | 点切到轻量档 | 台数与并行数一起降，列表立刻重排 |
| 连接范围卡 | 点停止 | 不再发新请求，已拿到的保留 |
