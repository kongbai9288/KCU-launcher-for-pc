## 计划生成

```
按权重排序全部服务器
  → 分出「测过且从没成功过」的一组（不主动探测）
  → 其余为候选
  → 新加的排到候选队首
  → 取前 N 台进入本次计划（N = 档位给的本次可连台数）
  → 剩下的标「超出本次范围」
  → N 台放进有界队列，最多 C 路同时在线（C = 档位给的并发）
```

| 档位 | 本次可连 N | 同时连接 C | 说明 |
| --- | --- | --- | --- |
| 标准 | 4 | 3 | 默认值，可在设置里改 2 / 4 / 6 / 全部 |
| 轻量 | 2 | 2 | 轻量机器自动降档，也可设为与标准一致 |
| 无界面 | 0 | 0 | 不加载界面，也不做列表探测 |

N 与 C 都是上限，不随服务器总数增长。新加服务器强制入队，但会挤掉候选里权重最低的一台，总数仍等于 N。

## 异步执行

| 编号 | 约束 |
| --- | --- |
| A01 | worker-pull：固定 C 个 worker 从有界队列取任务，取完一个才拿下一个。 |
| A02 | 单台有 deadline，超时跳过并记录，不阻塞其它台；失败不毁整批。 |
| A03 | UI 先渲染上次缓存结果，探测结果逐条增量写回，不等全部完成。 |
| A04 | 取消：停止按钮置 cancelled，在飞任务丢弃、队列清空、不再写新结果、不再发新请求；已完成的结果保留。 |
| A05 | 到顶后的策略是「排队 + deadline」，不是无限堆积、不是立刻重试、不是丢掉整批。 |
| A06 | 观测：本次可连、同时连接、在飞 / 队列、本次不连、进度条、上次同步时间。 |
| A07 | 探测结果与图标等元数据走有界缓存，刷新只取增量，重新获取清缓存全量重测。 |
| A08 | 范围外与无成功记录的服务器不产生任何网络请求。 |

## 失败历史与排序

| 状态 | 标记 | 是否主动探测 | 排序档 |
| --- | --- | --- | --- |
| 用户锁定 | `lock` | 是（不受裁剪） | 0，连不上也不动 |
| 本轮连上 / 缓存可用 | `ok` | 是 | 100 + 延迟 / 最近使用 / 人数 |
| 超出本次范围 | `probeSkip=out` | 否，保留上次结果 | 200 + 缓存权重 |
| 测过且无成功案例 | `probeSkip=never` | 否 | 300 + 缓存权重 |
| 曾成功、本轮连不上 | `ever && !ok` | 是（后续轮仍试） | 900 + 缓存权重 |

缓存权重取最近使用时间与上次延迟，不依赖本轮网络。锁定项永远排第一。

## 使用逻辑 12 项（022 增量）

| 编号 | 项 | 设计 |
| --- | --- | --- |
| L01 | 入口 | 服务器页首屏，连接范围卡在右栏 |
| L02 | 推荐与默认 | 锁定置顶，其余按权重取前 N 台连 |
| L03 | 缓存 | 范围外 / 无成功记录都用缓存结果；增量刷新 |
| L04 | 刷新 | 重新连接 = 增量；重新获取 = 清缓存全量；重新读取 = 只扫 servers.dat |

| L06 | 加载 / 取消 | 进度条 + 停止按钮，取消后 0 新请求 |
| L07 | 错误 / 降级 | 单台超时跳过；曾成功但本轮失败沉底；范围外用上次结果 |
| L08 | 关闭 / 残留 | 停止、切档、弹窗都不留浮层 |
| L09 | 权限确认 | 021 L09 不变，首次连接提示外传 IP / UUID |

| L11 | 性能 | 并发有上限、队列有界、总量卡档位、轻量自动降档 |
| L12 | 可发现 | 服务器页、设置 → 服务器与连接、首页推荐卡 |
